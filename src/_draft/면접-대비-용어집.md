## 4. 예상 질문과 답 (2026-11-24 추가)

### Strikers §3.5 "그래서 지금 고른다면 — Update + 타이머"

**Q. 표에는 Update + 타이머가 패턴마다 변수가 늘어난다고 했는데, 그건 어떻게 하실 건가요?**
- 답의 뼈대: 패턴마다 변수를 따로 두지 않고, **지금 쓰는 패턴 하나에 필요한 변수만** 둡니다.
  - `patternIndex` — 지금 몇 번째 패턴인지 (0~3)
  - `shotTimer` — 다음 발사까지 남은 시간 (`Time.deltaTime`으로 줄임, 전자레인지 과제와 같은 방식)
  - `shotCount` — 이번 패턴에서 몇 발 쐈는지
  - 패턴이 끝나면 `shotCount`를 0으로, `patternIndex`를 다음 번호로 바꿉니다(전자레인지 과제의 배열 + 인덱스 순환과 같은 방식).
- 이렇게 말하면 됨: "패턴이 4개여도 한 번에 하나만 실행되니까, 몇 번째 패턴인지 · 남은 시간 · 쏜 발 수 세 개만 두고 패턴이 바뀔 때 되돌리겠습니다."
- 더 물으면(패턴마다 클래스로 나누기 등): "그런 방법이 있다는 것은 알지만 아직 직접 해 보지 않았습니다. 다음에 공부할 목록에 있습니다." — 지어내지 않기

**Q. 그럼 처음에는 왜 코루틴으로 만들었나요?**
- 문서 그대로: "학원에서 배운 코루틴으로 만들고 싶다고 AI에 요청했습니다. 다른 방식과 비교해서 고른 것은 아닙니다. 비교는 문서를 쓰며 돌아본 것입니다."

**Q. 코루틴의 장점은 뭐라고 생각하나요?**
- 문서 표 그대로: "발사 순서가 코드 순서 그대로 읽히고, 패턴 하나가 함수 하나라 패턴을 추가하기 쉽습니다. 실제로 패턴 3종을 한 번에 추가했습니다(07.01)."
- 이어서: "다만 저는 `yield`를 직접 다뤄 본 적이 적어서, 고칠 때 제가 읽을 수 있는 Update 쪽을 고르겠다고 썼습니다."
